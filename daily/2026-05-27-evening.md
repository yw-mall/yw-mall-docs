## 🐛 排错记录

| 现象 | 根因 | 修法 |
|---|---|---|
| alice merchant login 报 "bcrypt: hashedPassword is not the hash of the given password" | 老 `Login` RPC 用 CachedConn，password UPDATE 后 Redis 仍读旧 hash | `redis-cli DEL cache:user:*` 清缓存（生产路径走 ChangePassword RPC 无此问题，是 dev fixture 直 UPDATE 引发） |
| bob accept 邀请报 "phone mismatch with invitation target" | reg-v2 后 user.phone 明文列为空，identifier 用 phone_hash 存 | AcceptInvitation 改走 `cryptox.Hmac(target_phone) == user.phone_hash` 等价比较 |
| shop-rpc backfill `Unknown column 'owner_id'` | 列实际是 `owner_user_id` | 改 SQL |
| Seed 数据 shop.owner_user_id 全为 0 (历史 bug) | 没走 applyShop 正式流程 | dev fixture 手工 UPDATE alice 为 shop_id=1 的 owner |
| FE accept.vue CORS to :18888 | Vite proxy 没覆盖 /api/ | vite.config.ts 加 /api → :18888 proxy；accept.vue 改用相对路径 |
