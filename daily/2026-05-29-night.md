### 关键架构决策

1. **Role 注入 session**：CreateSession 时 sessionPayload 带 Role + Perms，MerchantAuth
   middleware 在网关层校验；logic 层用 hasPerm helper 二次校验（owner 的 `["*"]`
   全开）—— 双层防御
2. **HMAC blind index**：phone / email 字段 cryptox.Hmac 用 MALL_FIELD_ENCRYPTION_KEY
   前 32 字节做模糊索引，AcceptInvitation 用 phone_hash 匹配而非明文 phone
3. **多 SKU 聚合回写**：sku.price/stock 修改后回写 product.price=MIN/stock=SUM，
   C 端「商品列表」「商品详情」零改造，复用既有 product 表展示逻辑
4. **Dashboard 聚合放 admin-api 而非 shop-rpc**：避免 shop-rpc 反向依赖 order/payment
   client，errgroup 在网关层并发；任一下游失败兜底返 0 不阻塞页面
5. **dev/prod parity 修正**：APISIX upstream env 化（host.containers.internal vs
   容器名），宿主 `/etc/hosts` 加 etcd1 解 advertise-client-urls 解析失败

### 用户主报告的 bug 修复列表

跨 6 个里程碑用户走查报告 + 修复（按时间序）：

4. 邀请注册 phone 列空 → HMAC vs phone_hash 而非明文
5. SkuMatrix 输入框不能编辑 → `@change` 改 `@update:model-value`（@change 只在 blur 触发）
6. first_value MySQL 8 保留字报错 → freightcommon.go SQL 列名加反引号
7. APISIX 503 → setup.sh upstream nodes env 化
8. C 端首页商品图片不显示 → product.images 是 csv 字符串非数组，FE api 边界 normalize
9. /merchant/v1/ledger 404 → merchant 版 wrapper logic 补全，强制 c.ShopId 防越权
10. etcd1 域名解析失败 → 用户 `/etc/hosts` 加映射

每个修复都遵循「需要最合适的修复，不要快修法」原则。
