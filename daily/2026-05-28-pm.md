## 🔧 主要交付

### T1 后端 3 个新 endpoint

`yw-mall-admin/internal/logic/refunds_logic.go` 加：
- `MerchantGetRefundDetail`（校验本店归属防越权）
- `MerchantInspectReturn`（需 `refund.inspect` perm, 仓管角色可调）
- `MerchantShipExchange`（需 `order.ship` perm, 仓管+店主可调）

顺手给原 `MerchantHandleRefund` 也补了 `refund.handle` perm 校验（之前漏了）。

路由：
```
GET    /merchant/v1/refunds/:id
POST   /merchant/v1/refunds/:id/inspect
POST   /merchant/v1/refunds/:id/ship-exchange
```

### T2 FE api/refunds.ts

`listRefunds / getRefund / handleRefund / inspectReturn / shipExchange` + `RefundItem` / `RefundDetail` / `RefundItemSku` 类型。

### T3 退款列表 + 详情（核心）

**list.vue**：8 状态 tab（待处理/同意待寄回/用户已寄回/仲裁中/已完成/已驳回/已退款）+ 表格 + 状态 tag 彩色 + 点击进详情。

**detail.vue（核心）**：
- **el-steps 进度条按 `refund_type` 动态步数**：
  - 仅退款 3 步：提交 → 商家处理 → 完成
  - 退货退款 5 步：提交 → 商家同意 → 用户寄回 → 商家验货 → 完成
  - 换货 6 步：提交 → 商家同意 → 用户寄回 → 商家验货 → **商家寄换货** → 完成
  - 当前 step 由 `status × type` 映射

- **3 个 action 按钮**按 `(status × type × perm)` 三维组合条件渲染：
  ```
  同意/驳回   : status=0 ∧ perm.refund.handle
  验货        : status=2 ∧ type∈{2,3} ∧ perm.refund.inspect
  寄换货      : status=3 ∧ type=3 ∧ perm.order.ship
  ```

- **3 个 modal**：
  - handle（textarea 同意/驳回理由）
  - inspect（radio 通过/不通过 + 说明）
  - ship-exchange（物流公司下拉 + 面单号）

- 含 SKU 列表 + 凭证图片预览（el-image preview-src-list）

### T4 路由 + 菜单

`/refunds` + `/refunds/:id` perm 守卫；菜单解锁。
