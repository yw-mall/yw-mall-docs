## 🎯 设计偏离记账（重要）

**原 design spec 6.2 写：** dashboard 聚合 RPC 放 shop-rpc，理由是「errgroup 并发调 4 服务，统一一处省 60% 延迟」。

**实施时改成放 admin-api logic 层**，原因：
1. shop-rpc 没引 order-rpc / payment-rpc client — 加上是「反向依赖」结构污染
2. admin-api 本来就有这些 client + errgroup 一样能并发
3. 少一跳（admin-api → 4 子服务 vs admin-api → shop-rpc → 4 子服务）
4. 验证：5 字段聚合实测 admin-api 一次返回，无延迟问题

design 是 north star 不是 strait jacket。这种实施时的小修正以「daily 透明记账 + commit message 说明」为准。

---

## 🎯 「今日营业额」字段的妥协说明

**原 spec** dashboard 4 核心指标包含「今日营业额」+ 「今日订单」。

**实际：** `order-rpc.ListShopOrders` 没暴露日期 filter，本期返「总订单数」替代。

**为什么没强行加日期 filter**：
- 需要改 order-rpc proto（加 `StartTime` / `EndTime` 字段）+ regen + logic 加 WHERE 条件
- proto 改动牵涉所有 order-rpc 消费者（mall-api、admin-api 等）的兼容
- M6 收尾不引爆这种跨服务 proto 改动；放到「日维度聚合 P1+ 单独 sprint」更合适

dashboard 5 字段实际是：
```
totalOrders / pendingShipments / pendingRefunds /
walletAvailable / walletFrozen
```

跟 spec 的「4 卡片」语义相似，只是「今日」改「总」。
