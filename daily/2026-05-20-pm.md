## 🧩 顺手解决的 env 拉起踩坑

把上午 commit `906be07` 没覆盖到的几个新坑也修了（commit 在 `906be07` 之后）：

| 坑 | 表象 | 修法 |
|---|---|---|
| 镜像 tag 不存在 | `bitnami/postgresql:17` / `edoburu/pgbouncer:1.23.1` 都 manifest unknown | 换 `library/postgres:17` / `edoburu/pgbouncer:v1.23.0-p0` |
| MinIO mc 容器报错 | `sh is not a recognized command` | minio/mc 新版本把 `mc` 当 entrypoint，要 `--entrypoint /bin/sh` |
| compose 网络名 | 脚本写死 `--network infra`，实际是 `env_infra` | 自动从 minio 容器探测网络名 |
| HAProxy 启动失败 | `could not resolve address 'pg3'` | 加 `init-addr last,libc,none` 容忍缺席副本 |
| PgBouncer auth 死循环 | "bouncer config error" | PgBouncer 1.21+ 必须显式 `auth_dbname=postgres` |
| pgbouncer 用户无 CONNECT mall | 同上 | `init-users.sql` 加 `GRANT CONNECT ON DATABASE mall TO pgbouncer` |
| pgbouncer FATAL "should not run as root" | compose 里写了 `user: "0:0"` | 删掉，让镜像默认 postgres 用户跑 |
| pg-init chicken-and-egg | pg-init 走 pgbouncer，pgbouncer 要 pgbouncer 用户存在 | pg-init PGHOST 改 pg-haproxy1（绕开 pgbouncer）|
| mongo --auth 下不能 rs.initiate | keyFile + auth 模式 localhost exception 限制 | 用 `MONGO_INITDB_ROOT_*` 让 entrypoint 预建 root 用户 |

这些全部在 906be07 落进 compose / config，下一台机器拉起不再踩。
