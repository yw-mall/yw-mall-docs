### 5. APISIX DNS 缓存修复（env）

mall-fe 真接通后调 `/api/shop/recommended` 502。trace：

- mall-api 直连 18888 OK（405 HEAD 合理响应）
- APISIX `:9080` 自己就 502
- 看 APISIX error log：试图连 `10.89.0.112`，但 nslookup 显示 mall-api 现在是 `10.89.0.175`
- **根因**：mall-api 容器之前 `force-recreate` 拿到新 IP，但 APISIX 是 4 天前启动的，把 upstream hostname 缓存固化在老 IP。跟 mall-fe nginx 经典 `resolver` 坑同源
- **修**：`apisix/config.yaml` 加：
  ```yaml
  apisix:
    dns_resolver:
      - "10.89.0.1"           # podman embedded DNS
    dns_resolver_valid: 30    # seconds
  ```
- 验证：重启 APISIX 后 `nginx.conf` 自动生成 `resolver 10.89.0.1 valid=30 ipv6=off`，业务接口 200。今后 mall-api recreate 30s 内自动 re-resolve，不再需要手动 restart APISIX

### 6. Loki + Promtail 日志聚合（env）

之前 yw-mall 容器日志没地方查（podman logs 临时看，没历史、没搜索）。方案选 Loki + Promtail + 复用 Grafana：

- `loki/loki-config.yaml`：Loki 3.2.1 单实例 + filesystem 存储，30 天保留，`:3100`
- `loki/promtail-config.yaml`：通过 podman socket（rootless `/run/user/1000/podman/podman.sock`）自动发现容器
  - yw-mall 流：按 `__meta_docker_container_name` regex 抽 `service` 标签
  - pipeline 解析 go-zero JSON 的 `@timestamp / level / caller / content / span / trace`，`level` 提为 label，`content` 作为日志正文（避免界面看到一坨 JSON）
- `grafana/provisioning/datasources/datasources.yml`：加 Loki datasource，url `http://loki:3100`，restart grafana 自动 provision
- `compose.yml`：加 `loki` + `promtail` 两服务到 `logs` profile，~250MB 内存

数据验证：`curl /loki/api/v1/label/service/values` 返回 17 个 yw-mall service 标签全部就绪：
```
mall-user-rpc, mall-product-rpc, mall-order-rpc, mall-cart-rpc, mall-payment-rpc,
mall-activity-rpc, mall-rule-rpc, mall-workflow-rpc, mall-reward-rpc, mall-risk-rpc,
mall-review-rpc, mall-logistics-rpc, mall-shop-rpc, mall-activity-async-worker,
mall-api, mall-admin-api, mall-fe
```

**使用**：
- Grafana http://localhost:3000 → Explore → Loki
- LogQL 示例：
  ```logql
  {service="mall-payment-rpc",level="error"}
  {stack="yw-mall"} |~ "alice"
  {service=~"mall-.*-rpc",level="error"}
  ```
- 实时 tail 绕过 Loki：`podman logs -f yw-mall-deploy_<svc>_1`
