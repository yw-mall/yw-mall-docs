## 🔧 上午：L1.6 收口（login-revamp P1 第一项 ✅）

**问题**：5 天前刚交付的「忘记密码」功能留了个安全口子——用户改完密码后，旧 token 在 Redis 里仍可用 30 分钟。咖啡馆 token 被偷 + 用户改密的现实场景下，小偷仍能访问。

**解法**：1 个 helper + 2 处 3 行调用，不动 proto、不动 Redis key 布局。
- 新增 `destroyUserSessionsByRole(ctx, svc, uid, role)`：按 `sessionPayload.Role` 过滤 `user_sessions:{uid}` 这个 Redis set，因为 admin_user.id 和 user.id 共享同一 set，必须按 role 区分否则会相互踢下线
- ChangePassword + ResetPasswordByCode 收尾调一下，best-effort 不阻塞密码改动

**实测验证 7/7 全过**：双设备 login + Redis 注入 role=admin 伪 session → 改密 → T1/T2 → 401 + 假 admin session+refresh 保留；user-rpc 日志精确打印 `kicked 2 user session(s) for uid=15`。

**埋下伏笔**：M1 商家工作台的 `role="merchant"` 直接受益——商家改密只清商家自己的 session，不影响同 uid 的 c-user / admin session。

### 核心架构（与原设计无偏离）

- **后端 RPC**：复用 mall-shop-rpc，加 8 个 staff/invitation method
- **HTTP 网关**：复用 yw-mall-admin（admin-api），加 `/merchant/v1/{staff,staff/invitations,invitations/accept}` 路由
- **数据模型**：3 张表中 M1 落 2 张（staff + invitation），shop_decoration 推到 M6
- **安全模型**：复用已有 `SessionAuthMiddleware{role:"merchant"}` + 加 perm 字段注入 session；上层 hasPerm 双层校验
- **前端**：复制 admin/ 脚手架（Vue3+Element+Vite），京东风设计令牌一致
- **APISIX**：加 `/merchant/*` 路由复用 mall-admin-api upstream
